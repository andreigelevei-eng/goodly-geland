# CONTENT ARCHITECTURE

Глобальная структура проекта Obzornik / Goodly-Geland.

## Главная идея

Репозиторий `goodly-geland` — это не набор случайных страниц, а фабрика тематических SEO-кластеров.

Каждая новая большая тема заводится как отдельный контур:

```text
topic → topic memory → article map → pages → CTA
```

Примеры тем:

```text
Goodly
YCLIENTS
КИС
Маркетинг жены
Нумерология мамы
Другие направления
```

## Обязательное правило

Перед генерацией статей по новой теме сначала создать структуру темы и её память. Нельзя сразу писать 57 статей без карты темы.

## Структура темы

Для каждой темы создаётся папка:

```text
src/content/topics/<topic-slug>/
```

Внутри:

```text
_topic.md              память темы, правила, позиционирование
_article-map.md        карта статей и очередность публикации
products/              обзоры продуктов, если есть
articles/              SEO-статьи темы
landing/               посадочные страницы, если нужны
```

Пример для Goodly:

```text
src/content/topics/goodly/
  _topic.md
  _article-map.md
  products/
    golos-i-harizma-v-tekste.md
  articles/
    kak-pisat-uznavaemye-teksty.md
    goodly-dlya-infoproduktov.md
    ...
```

## Почему так

Так мы не смешиваем разные направления. Goodly не смешивается с YCLIENTS, КИС, маркетингом жены или нумерологией мамы. У каждой темы свой смысл, аудитория, CTA, структура и память.

## Публичный URL

Публичные страницы должны строиться логически:

```text
/topics/goodly/
/topics/goodly/golos-i-harizma-v-tekste/
/topics/goodly/kak-pisat-uznavaemye-teksty/
/topics/yclients/
/topics/kis/
```

На старте допустимы короткие URL `/products/` и `/articles/`, но стратегическая структура — через `/topics/<topic>/`.

## Алгоритм работы при новой теме

Когда Андрей присылает тему, агент обязан:

1. Определить название темы.
2. Создать slug темы.
3. Создать `_topic.md`.
4. Создать `_article-map.md`.
5. Зафиксировать CTA и коммерческую цель.
6. Зафиксировать аудиторию.
7. Разложить тему на кластеры.
8. Только после этого создавать статьи.

## Нельзя

- Нельзя писать статьи без `_topic.md`.
- Нельзя смешивать разные темы в одной папке.
- Нельзя переносить память одной темы в другую.
- Нельзя использовать один CTA для всех тем без проверки.
- Нельзя раскрывать внутреннюю механику перепродажи покупателю.

## Можно

- Делать много статей внутри одной темы.
- Делать отдельные продуктовые обзоры.
- Делать сравнительные статьи.
- Делать посадочные страницы.
- Делать FAQ и JSON-LD на каждой странице.
- Вести CTA на Goodly, YCLIENTS, внешний сайт, мессенджер или другой указанный Андреем адрес.
